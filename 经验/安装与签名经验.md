# 安装与签名经验（SideStore）

> 从 `docs/` 提炼的可复用结论。文档正文不一定全对，以下以实测为准。

## 一、iOS 安装时的硬性规则

1. **扩展 bundle ID 前缀规则**：包内每个 `.appex` 的 `CFBundleIdentifier` 必须以主 App
   的 `CFBundleIdentifier` 为前缀（`<主ID>.<后缀>`）。违反时 installd 抛
   `IXErrorDomain Code=2 "Failed to set app extension placeholders for <主ID>"`，
   内层是 `Code=8 "does not match required prefix ... for parent"`。
   不要把它当成签名或证书问题排查。
2. **installd 扫的是“包内所有 `.appex`”**，不限于 `PlugIns/`。所以即使某个 `.appex`
   位于 `Extensions/` 这类非标准目录，它也会参与前缀校验，且必须是被正确签名的嵌套代码。
3. **SideSign 只枚举 `PlugIns/`**（`AppBundle.loadExtensions()`）。任何不在 `PlugIns/`
   的 `.appex` 既不会被改名，也不会被重签 —— 这就是“主 App 改了 ID、扩展没改”的典型来源。

## 二、SideStore 的 bundle ID 处理

- 默认开启 `appendTeamID`：主 App ID 变成 `<原ID>.<TeamID>`（TeamID 形如 `PSTNW3UN4R`，
  10 位）。因此只要包里有扩展，就一定存在前缀一致性风险。
- 扩展的 profile 注册走 `parentID + 原扩展 ID 去掉父 ID 的剩余后缀`，所以标准扩展
  （`PlugIns/` 内）会被正确改名。
- 排查时先看主 App 的 `CFBundleIdentifier` 是否带 `.XXXX` 后缀，再看扩展 ID 是否同前缀。

## 三、非标准扩展目录怎么处理

- 已知案例：YouTube 把 `AppMigrationExtension.appex` 放在 `YouTube.app/Extensions/`，
  该 bundle 没有 `NSExtension` 声明，只做换机数据迁移 → 可以直接删除，不影响使用。
- 清理规则务必要有边界：
  - 保留 `PlugIns/` 下所有 `.appex`（包括扩展里再嵌套的 `PlugIns`）；
  - 不要删 `.framework/` 内部的 `.appex`（属于 framework 自己的代码，删了会崩）；
  - 删除后再校验一遍前缀，避免留坑。
- 删完后 `SC_Info/Manifest.plist` 的 `SinfReplicationPaths` 会残留已删除路径，
  需按“文件是否存在”过滤（`removeMissingAppExtensionReferences`）。

## 四、排查顺序（经验）

1. 先确认错误来自哪一层：
   - `IXErrorDomain` / `installd` / `MobileInstallation`：包结构或签名问题；
   - `ApplicationVerificationFailed`：签名/证书/profile 问题；
   - `minimuxer` 的 `InstallApp(...)`：安装服务调用失败，错误体里通常带真实系统错误。
2. 解包 IPA 看三件事：主 App `CFBundleIdentifier`、所有 `.appex` 的 ID 与前缀、
   `.appex` 所在目录。
3. 若错误里的“parent”带了 `.XXXX` 后缀，几乎可以断定是 SideStore 改名 + 扩展漏改。

## 五、工具命令速查

```sh
# 列出所有扩展及其所在目录
unzip -Z1 App.ipa | grep -i "appex/Info.plist"

# 读主 App 与扩展的 bundle id（二进制 plist 也能读）
plutil -p Payload/App.app/Info.plist | grep CFBundleIdentifier

# 模拟器编译验证（不需要证书）
xcodebuild -project AltStore.xcodeproj -scheme SideStore -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/sidestore-dd CODE_SIGNING_ALLOWED=NO build
```
