# YouTube IPA 安装失败：应用扩展 bundle ID 前缀不匹配

- 时间：2026-11-27 14:45
- 模型：豆包
- 影响文件：`SideStore/Core/Operations/PipelineOperations/ResignAppOperation.swift`

## 现象

安装 YouTube（秋名山 YTLPlus 21.44.4 等 mod 包）时，最后一步由 minimuxer 通过
`installation_proxy_install` 安装，系统返回：

```
InstallApp(Failed to install IPA, error: (UnknownErrorType("APIInternalError
(Error Domain=IXErrorDomain Code=2 "Failed to set app extension placeholders for
com.google.ios.youtube.PSTNW3UN4R" ... NSUnderlyingError Code=8
"Attempted to set app extension placeholder promise with bundle ID
com.google.ios.youtube.AppMigrationExtension that does not match required prefix of
com.google.ios.youtube.PSTNW3UN4R. for parent")))
```

## 根因

1. 安装时 SideStore 默认把主 App 的 bundle ID 加上 `.<TeamID>` 后缀
   （这里 TeamID = `PSTNW3UN4R`），于是主 App 变成 `com.google.ios.youtube.PSTNW3UN4R`。
2. iOS 的 installd 会把包内**所有** `.appex` 都登记为 app extension placeholder，
   并要求扩展 bundle ID 以主 App bundle ID 为前缀（Apple 的硬性规则），否则抛
   `IXErrorDomain Code=8 Mismatched bundle IDs`。
3. SideSign 的 `AppBundle.loadExtensions()` 只扫 `PlugIns/`。而 YouTube 把
   `AppMigrationExtension.appex` 放在 `YouTube.app/Extensions/`（非标准目录，
   该包没有 `NSExtension` 声明，只用于换机时迁移应用数据）。
   于是这个扩展既不会被改名、也不会被重签名，最终主 App ID 带了后缀而扩展 ID 没带，
   前缀规则不成立 → 安装失败。

实测（解包用户提供的 IPA 后枚举）：

```
PlugIns/IntentsExtension.appex                      com.google.ios.youtube.IntentsExtension
PlugIns/NotificationContentExtension.appex          com.google.ios.youtube.NotificationContentExtension
PlugIns/NotificationServiceExtension.appex          com.google.ios.youtube.NotificationServiceExtension
PlugIns/ShareExtension.appex                        com.google.ios.youtube.ExternalShareExtension
PlugIns/WidgetKitExtension.appex                    com.google.ios.youtube.WidgetKitExtension
Extensions/AppMigrationExtension.appex              com.google.ios.youtube.AppMigrationExtension   ← 非托管
```

## 修复

在 `ResignAppOperation.prepareAppBundle` 中、准备 plist 与签名之前：

1. 递归扫描包内 `.appex`，删除**未被 `PlugIns/` 托管**的扩展
   （`Extensions/` 等非标准目录）。保留规则：
   - 任何位于 `PlugIns/` 下的 `.appex`（含扩展内部再嵌套的扩展）都保留，交由 SideSign 改名+重签；
   - 位于 `.framework/` 内部的 `.appex` 属于 framework 代码，不删，避免破坏 framework。
2. 删除后再执行一次一致性校验：包内残留的每个 `.appex`，其 bundle ID 必须以主 App 新
   bundle ID 为前缀。不合规时抛出可读错误（列出路径与 bundle ID），而不是把 installd 的
   IXErrorDomain 错误原样丢给用户。
3. `SC_Info/Manifest.plist` 的 `SinfReplicationPaths` 由既有的
   `removeMissingAppExtensionReferences` 清理掉已删除文件的条目（在本轮删除之后执行）。

AppMigrationExtension 只用于设备迁移时的数据搬迁，删除后不影响 YouTube 正常登录与播放。

## 验证

- 用真实 IPA（`YouTube_21.44.4_YTLPlus6.0b2_iOS17.0+_秋名山.ipa`）完整解包，
   以脚本复现同一套扫描/删除规则：只删掉 `Extensions/AppMigrationExtension.appex`，
   5 个 `PlugIns/` 扩展全部保留。
- 另外用 21.40.5 巨魔版 IPA 复核：`Extensions/` 是空目录，不会误删任何东西。
- 编译验证：模拟器 target 编译通过（见“当前开发进度”文档）。

## 注意

- 该修复只在 SideStore 侧生效；设备上若仍用旧版 SideStore / 旧
  `LiveContainer+SideStore.ipa`，安装 YouTube 依旧会报同样的错，需要重新打包安装。
- 若以后遇到别的 App 把扩展放在 `AppClips/`、`Frameworks/` 等目录，同一套校验会给出明确报错。
